    int V;

Meaning:

🔵 6. Parallel BFS (Important)
Step 1: Initialization
vector<bool> visited(V, false);
queue<int> q;

visited[start] = true;
q.push(start);
visited → avoids revisiting nodes
queue → stores nodes for BFS
Start node is marked visited
Step 2: Main Loop
while (!q.empty())

Runs until all nodes are processed

Step 3: Level Processing
int size = q.size();

👉 This ensures:

We process one level at a time
Enables parallel processing of same-level nodes
Step 4: Parallel Loop
#pragma omp parallel for
for (int i = 0; i < size; i++)
Multiple threads process nodes simultaneously
Step 5: Critical Section (Very Important)
#pragma omp critical

Used when:

Accessing shared queue
Printing output

👉 Why needed?
To avoid:

Race conditions
Data corruption
Step 6: Node Processing
node = q.front();
q.pop();
cout << node;
Removes node from queue
Prints it
Step 7: Neighbor Processing
if (!visited[neighbor]) {
    visited[neighbor] = true;
    q.push(neighbor);
}

👉 Done inside critical section to:

Avoid duplicate insertions
Maintain correctness
🔵 BFS Summary
Uses queue
Works level-by-level
Parallelism applied to nodes at same level
🔴 7. Parallel DFS
Function:
parallelDFSUtil(int node, vector<bool> &visited)
Step 1: Check and Mark
#pragma omp critical
{
    alreadyVisited = visited[node];
    if (!visited[node]) {
        visited[node] = true;
        cout << node;
    }
}

👉 Ensures:

Only one thread updates visited
Prevents duplicate visits
Step 2: Stop Condition
if (alreadyVisited) return;
Avoids infinite recursion
Step 3: Parallel Neighbor Traversal
#pragma omp parallel for
for (int i = 0; i < adj[node].size(); i++)
Processes neighbors in parallel
Step 4: Task Creation
#pragma omp task
parallelDFSUtil(neighbor, visited);

👉 Each recursive call becomes a parallel task

🔴 Starting DFS
#pragma omp parallel
{
    #pragma omp single
    {
        parallelDFSUtil(start, visited);
    }
}
Explanation:
parallel → creates threads
single → only one thread starts recursion
Other threads execute tasks

⚠ Important Concepts (Exam Focus)
🔸 1. Race Condition

When multiple threads access shared data simultaneously → incorrect results

✔ Solved using:

#pragma omp critical
🔸 2. Why BFS Parallel?
Nodes at same level are independent → can run in parallel
🔸 3. Why DFS uses tasks?
DFS is recursive → tasks allow parallel recursion
🔸 4. Limitation
Too many critical sections reduce performance
Parallel overhead sometimes > benefit
🎯 Viva Questions & Answers
❓ Q1: What is BFS?

👉 Traverses graph level by level using queue.

❓ Q2: What is DFS?

👉 Traverses graph depth-wise using recursion or stack.

❓ Q3: Difference between BFS and DFS?
BFS	DFS
Level-wise	Depth-wise
Uses queue	Uses stack/recursion
Finds shortest path	Does not guarantee shortest
❓ Q4: What is OpenMP?

👉 API for parallel programming in C/C++ using threads.

❓ Q5: What is #pragma omp parallel for?

👉 Splits loop iterations among multiple threads.

❓ Q6: Why use critical?

👉 To prevent race conditions while accessing shared data.

❓ Q7: What is a task in OpenMP?

👉 A unit of work executed by any available thread.

❓ Q8: Why BFS is easier to parallelize than DFS?

👉 Because BFS processes independent nodes at same level.

❓ Q9: Why output order changes?

👉 Due to parallel execution of threads.

❓ Q10: Time complexity?

👉 Same as normal:

BFS → O(V + E)
DFS → O(V + E)
🧠 Easy Memory Trick
BFS → Queue + Level + Parallel loop
DFS → Recursion + Task + Parallel

🔷 1. Difference between BFS and DFS
BFS	DFS
Traverses level by level	Traverses depth first
Uses queue	Uses stack/recursion
Finds shortest path	Does not guarantee shortest path
More memory (stores level nodes)	Less memory
Easier to parallelize	Harder to parallelize
🔷 2. Why queue in BFS?

👉 Queue follows FIFO (First In First Out)

✔ In BFS:

First visited node is processed first
Ensures level-wise traversal

📌 Example:

Level 0 → Level 1 → Level 2

👉 Queue helps maintain this order

🔷 3. Why recursion in DFS?

👉 DFS goes deep into graph

✔ Recursion:

Automatically uses call stack
Keeps track of previous nodes

📌 So:

Easy to implement
Matches DFS nature (go deep → backtrack)
🔷 4. What is OpenMP?

👉 OpenMP is an API for parallel programming in C/C++

✔ It:

Uses multiple threads
Works with #pragma directives

📌 Example:

#pragma omp parallel for

👉 Used to speed up programs using multiple cores

🔷 5. What is Race Condition?

👉 When multiple threads access same data simultaneously

✔ Leads to:

Wrong results
Data inconsistency

📌 Example:
Two threads updating same variable at same time

🔷 6. Why critical section needed?

👉 To avoid race condition

✔ Only one thread at a time can execute it

📌 Example:

#pragma omp critical

👉 Used when accessing:

Queue
Shared variables
Visited array
🔷 7. What is Task Parallelism?

👉 Work is divided into independent tasks

✔ Each task runs in parallel

📌 Example in DFS:

#pragma omp task
parallelDFSUtil(neighbor, visited);

👉 Each recursive call = one task

🔷 8. Adjacency List vs Matrix
Adjacency List	Adjacency Matrix
Uses vectors/lists	Uses 2D array
Space efficient	Uses more memory
Faster for sparse graph	Good for dense graph
Easy neighbor traversal	Fast edge checking
🔷 9. Time Complexity

👉 Same as normal traversal:

BFS → O(V + E)
DFS → O(V + E)

Where:

V = vertices
E = edges
🔷 10. Why Parallel DFS is Difficult?

👉 Because DFS is sequential by nature

Problems:

Depends on previous steps
Uses recursion (hard to divide work)
Shared visited array → race condition
Too many tasks → overhead

👉 So:

Hard to efficiently parallelize compared to BFS
